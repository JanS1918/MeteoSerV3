2. REGLA DE ORO: DISEÑO → CÓDIGO → FUNCIONAL
═══════════════════════════════════════════════════════════════════════════════

Cuando diseñes un nuevo componente:

PASO 1: CÓDIGO PRIMERO
├─ Crea la clase/función
├─ Implementa la lógica COMPLETA
├─ SIN dejar TODO pendiente
└─ SIN comentarios del tipo "TODO: implementar X"

PASO 2: PRUEBA INMEDIATAMENTE
├─ Crea tests
├─ Verifica que funcione
├─ Ejecuta: python archivo.py
└─ ✅ DEBE PASAR SIN ERRORES

PASO 3: DOCUMENTA LO QUE EXISTE
├─ Escribe .md describiendo QUÉ CÓDIGO EXISTE
├─ NO escribas sobre funciones "planeadas"
├─ Cada doc debe apuntar a código real
└─ Vincula a líneas exactas: [punto_rocio](core/indices/environmental_indices.py#L4756)

PROHIBIDO: Diseño → Documento → Esperar a que alguien lo implemente
OBLIGATORIO: Diseño → Código Funcional → Documento
