## 🔑 Conceptos Clave

### 🎯 Validación Proactiva (NUEVA)
Valida ANTES de aplicar cambios
- Detecta gaps de especificación
- Bloquea cambios incompletos
- 100% prevención
- < 1 segundo de latencia

### 🔄 Validación Reactiva (EXISTENTE)
Valida DESPUÉS de aplicar cambios
- Duelo automático
- Monitoreo continuo
- ~95% detección
- 2-4 semanas de latencia

### 🛡️ 4 Capas de Protección
1. Proactivo (Propuesta)
2. Duelo (Aplicación)
3. Monitoreo (Operación)
4. Humano (Supervisión)

### 📊 Impacto
- Tiempo detección: 2-4 semanas → < 1 segundo
- Cambios bloqueados: 0% → 95-99%
- Daño: 5-10% → 0%
- Confianza: 30% → 95%

## 🎓 Glosario

| Término | Definición |
|---------|-----------|
| **Validación Proactiva** | Valida antes de aplicar, previene problemas |
| **Validación Reactiva** | Valida después de aplicar, detecta problemas |
| **Especificación** | Requisitos que debe cumplir una fórmula |
| **Implementación** | Código que ejecuta la fórmula |
| **Gap** | Diferencia entre especificación e implementación |
| **Duelo** | Comparación automática de fórmulas |
| **Watchdog** | Monitor de cambios y protector del sistema |
| **Capa** | Línea de defensa independiente |
| **Block** | Rechazar y congelar (de un cambio) |
| **Rollback** | Revertir a versión anterior |
| **Enhancement Factor** | Corrección f(T,P) para presión real |
| **IAPWS-95** | Ecuación de Wagner-Pruß para vapor |
| **Hardy NIST** | Fórmula con Enhancement Factor |
