5. ARQUITECTURA EN SÍNTESIS
═════════════════════════════════════════════════════════════════════════════

PRINCIPIO CERO (fundamental):
  "El sistema NO aprende por defecto. Solo aprende cuando contexto es limpio."

5 CAPAS:

[CAPA 1] CLASIFICACIÓN DE CONTEXTO
├─ Entrada: sensores + REST2
├─ Decide: ¿Es seguro aprender?
├─ OUTPUT: contexto {bloqueado | degradado | limpio}
└─ Ejemplos de bloqueo: sol < 15°, lluvia, niebla, nubes rápidas

[CAPA 2] APRENDIZAJE SEPARADO
├─ A) CORRECTIVO (lento, profundo)
│  ├─ Corrige sesgos sistemáticos de REST2
│  ├─ Ajusta Kt_local (máximo ±10%)
│  ├─ Memoria: 14 días
│  └─ Necesita: >= 20 observaciones limpias
├─ B) DIAGNÓSTICO (rápido, superficial)
│  ├─ Detecta calima, ensuciamiento, nubosidad fina
│  ├─ NUNCA corrige radiación, solo flags de confianza
│  └─ El 80% de autoengaños evitados aquí
└─ Resultado: ajustes de peso + flags de diagnóstico

[CAPA 3] PUBLICACIÓN CON JERARQUÍA
├─ Estados radiativos: GHI, DNI, DHI, POA, Rn_noche, flags
├─ Cada uno publica: {valor, confianza, contexto, fuente}
├─ Jerarquía por índice:
│  ├─ WBGT: prioritarios [POA, DNI, DHI], secundarios [GHI]
│  ├─ ET0:  prioritarios [DNI, DHI, POA], secundarios [GHI]
│  └─ T_min: prioritarios [Rn_noche], no_usar [GHI]
└─ Consumo inteligente respeta jerarquía + umbrales

[CAPA 4] VALIDACIÓN CRUZADA
├─ Radiación alta + T no sube → radiación sospecha
├─ Radiación baja + T sube mucho → temperatura sospechosa
├─ Penaliza confianza global si balance no OK
└─ Evita que un sensor defectuoso engañe al sistema

[CAPA 5] ORQUESTADOR CENTRAL
├─ Integra todas las capas en un ciclo
├─ Flujo: contexto → aprendizaje → validación → publicación → fusión
├─ Fusión inteligente con sensor real (pesos dinámicos)
└─ Publicación en bus con confianzas finales
