ARTÍCULO I - SOBERANÍA GEOGRÁFICA
----------------------------------
Toda altitud utilizada en cálculos físicos, atmosféricos o astronómicos
DEBE provenir exclusivamente del bus bajo el campo "altitud_srtm".

Fuente autorizada: SRTM (Shuttle Radar Topography Mission)
Resolución: ±10m vertical, 30m horizontal
Proveedor: Open-Elevation API / LocationEngine

Violación: Uso de altitud hardcoded o calculada localmente
Sanción: Alerta crítica + bloqueo del cálculo


ARTÍCULO II - SOBERANÍA ASTRONÓMICA SOLAR
------------------------------------------
Toda posición solar utilizada en cálculos de radiación, UV, nubosidad
o índices bioclimáticos DEBE provenir exclusivamente del bus bajo los
campos "elevacion_solar" y "azimut_solar".

Fuente autorizada: SPA NREL (Solar Position Algorithm)
Precisión: ±0.0003° (0.5 segundos de arco)
Método: Reda & Andreas 2004 / NREL Technical Report

Violación: Cálculo local de posición solar (ej. calcular_posicion_sol())
Sanción: Alerta crítica + bloqueo del cálculo


ARTÍCULO III - SOBERANÍA ASTRONÓMICA LUNAR
-------------------------------------------
Toda posición lunar utilizada en validación nocturna, nubosidad o índices
biológicos nocturnos DEBE provenir exclusivamente del bus bajo los campos
"arco_lunar_elevacion_deg", "arco_lunar_azimuth_deg" e "iluminacion_lunar".

Fuente autorizada: Meeus ELP2000 (60 términos principales)
Precisión: ±0.5° posición, ±1% iluminación
Método: Jean Meeus "Astronomical Algorithms" 2nd Ed.

Violación: Cálculo local de fase/posición lunar
Sanción: Degradación de confianza a 0% + warning crítico


ARTÍCULO IV - TRAZABILIDAD OBLIGATORIA
---------------------------------------
Todo cálculo que dependa de SRTM/Solar/Lunar DEBE publicar su fuente
en campos de trazabilidad:

- "fuente_altitud": ["SRTM", "manual_fallback", "manual_fallback_error"]
- "rest2_fuente_astronomica": ["SPA_NREL_V42.6", "REST2_interno"]
- "nubosidad_validacion_lunar": [True, False]

Violación: Uso de datos sin publicar fuente
Sanción: Datos marcados como "no_confiable"


ARTÍCULO V - WATCHDOG DE INTEGRIDAD
------------------------------------
El sistema DEBE validar al inicio de cada ciclo que:

✅ altitud_srtm != None
✅ elevacion_solar != None (durante el día)
✅ arco_lunar_elevacion_deg != None (durante la noche)
✅ fuente_altitud == "SRTM" (óptimo)

Violación: Datos críticos ausentes del bus
Sanción: Alerta crítica + degradación a modo seguro

└───────────────────────────────────────────────────────────────────────────┘

ESCENARIO 1: SRTM no disponible
Respuesta:
  1. Logger.warning("⚠️ SRTM no disponible, usando fallback manual")
  2. fuente_altitud = "manual_fallback"
  3. Continuar con altitud de configuración
  4. Publicar alerta_srtm_fallback = True

ESCENARIO 2: SPA NREL falla
Respuesta:
  1. Logger.critical("🚫 SPA NREL falló")
  2. Intentar calcular con algoritmo interno REST2
  3. rest2_fuente_astronomica = "REST2_interno"
  4. Degradar precisión a ±0.1°

ESCENARIO 3: Meeus lunar falla
Respuesta:
  1. Logger.warning("⚠️ Posición lunar no disponible")
  2. Usar solo parámetros atmosféricos para nubosidad nocturna
  3. nubosidad_validacion_lunar = False
  4. Mantener confianza en 60%

ESCENARIO 4: Bus corrupto
Respuesta:
  1. Logger.critical("🚫 BUS CORRUPTO - Integridad violada")
  2. Detener publicaciones no críticas
  3. Reinicializar bus desde configuración
  4. Recargar SRTM/SPA/Meeus
